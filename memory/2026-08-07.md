## DF-017.2 — End-to-End CLI Smoke Tests (apps/cli)

Created `apps/cli/__tests__/` (integration.test.ts, e2e.test.ts, helpers.ts,
mock-repository/ fixture). 48 CLI tests total (was 8). All fake providers, no
network, all filesystem writes confined to OS temp dir.

### Key findings / decisions
- **Found & fixed a real bug in `orchestrator.ts`:** commander's `.action()`
  passes `(args..., opts, thisCommand)` — the Command is the **last** argument,
  not the first. All `async (cmd) =>` handlers were receiving the options
  object, so `cmd.name` threw and *every* command via `run()` was broken.
  Rewrote actions to `async (...args) => { const cmd = args[args.length-1]; }`.
  This was a bug fix, not a feature (task said no new features).
- Commander's `parseAsync(argv)` in "node" mode slices `argv[2:]`, so tests must
  pass `['node', 'devforge', ...realArgs]`.
- `@devforge/logger` is pino → writes to fd 1, bypassing `process.stdout.write`
  spy. Silence it in tests with `vi.mock('@devforge/logger', ...)`.
- CLI's default `FakeModelProvider` never returns valid plan/patch JSON (its
  deterministic branches key off `request.model`, which the CLI never sets), so
  e2e heavy commands degrade gracefully; deterministic success paths live in
  integration tests where providers are injectable.
- `discoverRepository`/workspace `findWorkspaceRoot` walk up to filesystem root
  when no workspace marker found → workspaceRoot can be `/` (not used by git
  service, but surprising).
