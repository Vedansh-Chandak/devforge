### parser-typescript change (upstream, justified)
Parser only captured `ts.ExportDeclaration` nodes for `export {…} from …`, so
`export class Foo`, `export interface I`, etc. produced NO export edges →
`SymbolResolver` never flagged exported symbols and `findExports()` was broken.
Added `recordExportedDeclaration()` in `visit()` that synthesizes an export
declaration for any class/interface/enum/function/type-alias carrying the
`export` modifier. 11 parser tests still pass.

### Important linker/graph reality (documented for future me)
- File-namespace nodes (`namespace` kind, name = file path) are NOT real graph
  nodes — `addEdge` only records edges whose endpoints exist via `addNode`.
  So `allSymbols()`/`moduleSymbols()` return only declared symbols; no module
  entities.
- Heritage (`implements`/`extends`) edges only link symbols in the SAME parsed
  file (linker looks up target in the file-local symbol map). `findImplementations`
  of a cross-file interface returns `[]`. Tests must use same-file fixtures.
- No `calls`/`references` edges are produced by the linker, so `findCallers`
  effectively returns heritage/extends relations only.
- `findDependencies` defaults to maxDepth=Infinity (transitive), NOT direct.
