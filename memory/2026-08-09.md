# 2026-08-09

## DF-020 — VS Code extension + language server

Built `extensions/vscode` on top of `@devforge/cli`/brain/planner/executor
(reuses engine, no duplication). 311 deterministic tests across 25 files.

### Architecture
VS Code → ExtensionHost → DevForgeClient → CliAdapter (`@devforge/cli`) →
SessionManager (sessions/history) → commands → providers (chat/diff/tree/
diagnostics/progress) + vscode-languageclient bridge → `dist/language-server.js`
(document store, symbol extractor, diagnostic engine, code actions).
In-process LSP via IPC. `ExtensionHost` takes an injectable `HostBundle` so the
entire activation path is testable against the vscode mock.

### Decisions worth remembering
- Extension is **CommonJS** (`"type"` unset) because `vscode-languageclient/
  languageserver` 9.0.1 are CJS without an `exports` map. tsconfig overrides
  base: `module: CommonJS`, `moduleResolution: Node`.
- Added `"default": "./dist/index.js"` to `@devforge/cli`'s `exports` map for
  CJS `require(esm)` interop — compiled CJS rewrites dynamic `import()` to
  `require()`, which previously threw "No exports main defined". 40 exports.
- vitest aliases `vscode` → `tests/mocks/vscode.ts` AND
  `vscode-languageclient/node` → `tests/mocks/vscode-languageclient.ts`
  (that module requires real vscode at load).
- `LanguageClient.isRunning` is a **method**, so our `LanguageClientLike`
  abstraction declares `isRunning(): boolean`.
- Doctor health-check signals use `file: ''` → dropped by the diagnostics
  collection (editor markers) by design; they surface in the diagnostics
  tree. Test asserts on `set()` call, not collection entries.
- Tree provider maps collapsible states via explicit `COLLAPSIBLE_STATE_KEY`
  (`none|collapsed|expanded` → enum keys); `toUpperCase()` never matched.
- Absolute import depth in tests matters: `tests/*.ts` → `../src/`,
  `tests/services/*.ts` → `../../src/`.
