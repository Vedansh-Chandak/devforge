### Bugs fixed this session (8 failing tests → 0)
1. **Getter snapshot on destructure**: `scriptedCodingModel({ get calls() })` snapshotted `calls` at destructure time. Changed interface to `getCalls: () => number` (also `scriptedReasoningModel` → `getAnalyzeCalls`/`getDecideCalls`). Tests updated to call `getCalls()`.
2. **`countingPatchEngine`**: `Object.assign(wrapper, { get calls() })` copies the *value* (0), not the getter. Switched to `Object.defineProperty(wrapper, 'calls', { get: () => calls })` with a type cast for the intersection return type.
3. **DefaultPatchEngine name**: test expects `name` to contain `default-patch-engine`; previously it used model name verbatim. Now `default-patch-engine(${model.name})` or bare `default-patch-engine`.
4. **Diagnostics test-failure parsing**: `^(?:FAIL|×|✕)` matched BOTH the `FAIL foo > bar` header AND the `× Expected 1 but got 2` line → 2 diagnostics, expected 1. Changed regex to `^[×✕]\s+(.+)$` so only the failure-message line is a diagnostic.
5. **Diagnostics summary counts**: after fix #4 there were 2 compiler + 1 test = 3 errors, but test expects `'2 errors'`. `buildSummary` now skips `TEST`-category diagnostics when counting errors/warnings (test failures reported via their own diagnostics).
6. **Coding-model deep-copy test**: passed `[PATCHES_A]` but called `generatePatch` twice → model "exhausted". Test fixture changed to `[PATCHES_A, PATCHES_A]` (conflicted with the legit "throws when exhausted" test).
7. **repair.ts budget errors leaking as throws**: `run()` now wraps initial `applyAndVerify` AND `runRepairLoop` in try/catch; converts `RepairBudgetExceededError` and `ReasoningError` into `BUDGET_EXCEEDED` reports (with last-known diagnostics) instead of propagating. This fixed "rolls back transaction", "exceeds patch generation budget", "exceeds verification run budget".
