# DF-029A Stop-Condition Report

**Phase:** DF-029A — CLI packaging & npm readiness
**Date:** 2026-08-20
**Stop condition:** `@devforge/cli` is a production-ready, publishable npm package: self-contained build (no workspace-only resolution), correct ESM + CJS exports (VS Code interop intact), validated package metadata, clean-package install test, runtime dependency audit, package content verification, green root check-types/build/test/lint, and `DF-029A-Stop-Condition-Report.md` written — with **no publish made and no commit staged**.

## 1. Objective and scope

Make `@devforge/cli` a package a developer can `npm install -g` and run as `devforge doctor/ask/plan/run`. Because the 14 `@devforge/*` sibling packages (brain, config, errors, execution, knowledge-graph, logger, model-provider, parser-typescript, planner, prompt-composer, repository-indexer, runtime, symbol-graph, tools) are **not yet published**, the CLI's production artifact must inline them at build time so the installed tarball has zero workspace-only resolution. Only real npm dependencies may be declared: `commander`, `zod`, `pino`, `pino-pretty`, `typescript`.

Out of scope (future): publishing the sibling `@devforge/*` packages, npm publish/release automation, workspace changes to model-provider/Brain/Planner/Executor semantics, real-LLM smoke under CI. **No publish and no commit were made.**

## 4. Build strategy (runtime bundling)

The previous build (`tsc -p tsconfig.json`) emitted a multi-file `dist` whose imports resolved `@devforge/*` through node_modules — correct in-repo, broken for a standalone install. The new `scripts/build.mjs`:

1. **Inline all workspace packages.** esbuild `alias` maps each `@devforge/<pkg>` to `packages/<pkg>/src/index.ts`, so the CLI bundle contains the full runtime closure of brain/model-provider/execution/planner/parser-typescript/etc. The build is also independent: it does not depend on sibling `dist` output.
2. **Externalize only real deps.** `external = [commander, zod, pino, pino-pretty, typescript]` — precisely the declared `dependencies`. `pino-pretty` is a pino transport target (logger config string) and is declared as a runtime dep so the transport resolves.
3. **Dual format for VS Code interop.** The extension is CommonJS and does `await import('@devforge/cli')` at runtime plus type-imports in `src/types.ts`. `dist/index.cjs` (require/`main`/`default` condition) + `dist/index.js` (import) + a CJS `exports.require` condition cover every resolution path. Verified in the isolated install (`cjs-ok`/`esm-ok` probes + extension check-types).
4. **Bundled sizes:** `main.js` ≈ 482 KB, `index.js` ≈ 495 KB, `index.cjs` ≈ 500 KB, `index.d.ts` ≈ 74 KB. Whole published `dist` ≈ 1.5 MB, no sourcemaps shipped.

## 5. Type surface

`dist/index.d.ts` from `dts-bundle-generator` inlines every `@devforge/*` type node the CLI's public API references (`ModelProvider`, `DevForgeRuntime`, `ExecutionPlan`, `ExecutionReport`, `CodingReport`, `Planner`, `Executor`, etc.), leaving **no remaining `@devforge/` imports** (régrep: only comment mentions remain). A tiny build-time normalization replaces the `typeof output`/`typeof progress` module-namespace references (unrepresentable in a single-file bundle) with structural types over the already-hoisted top-level declarations. The published package is therefore fully typed for external TypeScript consumers with **zero workspace dependency**, confirmed by a strict `tsc --noEmit module nodenext` consumer test in the isolated install.
